# 自我修正与方法论

> **如果只能看本仓库的一份文档，看这份。**
>
> 这篇文章记录的是**我犯过的错**，以及每次错在"推理的哪一步"。
> 性能数字会过时，硬件会换代，但"怎么判断一个结论可不可信"不会。
>
> 做 Infra 最怕的不是不知道，而是**拿着一个看起来合理但没验证过的归因去修生产事故**。

## 一、六次推翻自己的结论

| # | 原结论 | 证伪方式 | 最终真相 |
| --- | --- | --- | --- |
| 1 | `cudaMallocAsync` 问题是跨架构共性 | A10 + P100 对照实验 | **仅 RTX 5060/Windows/8G 复现**；P100/A10 零影响 |
| 2 | P100 尾部 10.2s 毛刺是物理现象 | WebSocket 重测 | **毛刺从未存在**，是 2s 轮询的量化假象 |
| 3 | 容器化开销 +5.8% | 拆热惯性/整卡口径/page cache | **净开销 < 1%** |
| 4 | LoRA 畸形根因是数据集多样性 | 换一致数据集重训仍失败 | 根因是**生成分辨率与训练构图不匹配** |
| 5 | AdamW8bit 在 sm_60 上算错 | 第 4 条的连带平反 | v1/v2 从未在正确画幅下被评测过，**优化器一直无辜** |
| 6 | Proxmox 透传拿不到 per-process 显存归属 | 用户质疑后复测 | `query-compute-apps` **可用**；空表 ≠ 不支持 |

## 二、逐条复盘：错在哪一步

### 修正 1：一台机器的样本不能支撑普遍性断言

**当时的推理链：**

```
5060（Blackwell）有问题            ✅ 实测
P100（Pascal）用 native 正常运行    ✅ 实测
        ↓  ❌ 无效推理
"所以 P100 用 cudaMallocAsync 也会有问题"
        ↓
"所以是跨架构共性"
```

**中间那一步从未被验证。** P100 从头到尾跑的都是 native，对照实验根本没做过——
我把"没测过"当成了"测过且有问题"。A10 的对照实验直接证伪：完全无差异。

**教训：**

1. **区分"实测过"和"推断的"** —— 写结论前把证据链逐条列出，标注哪些是实测、哪些是推断。
2. **措辞必须收窄到实测范围** —— "在 RTX 5060/Windows/8GB 上必须加该参数"是可靠的；"跨架构共性"不是。
3. **多变量差异无法定因** —— 5060 与 A10 有 5 个变量同时不同，任何单一归因都是猜测。

> 修正后的诚实结论：当前证据**支持"Windows WDDM 显存模型"假设**，但**无法排除"8GB 显存压力"假设**——
> 5060 同时是唯一的 Windows 机器和唯一的 8GB 机器，**这两个变量在现有环境中始终绑定**。
> 要分离需要 Linux+8GB 或 Windows+大显存的机器。**在能分离之前，就承认定因未完成。**

### 修正 2 & 3：先确认量具，再相信读数

这两次是同一类错误：**把测量误差当成物理现象。**

| 现象 | 以为是 | 实际是 |
| --- | --- | --- |
| P100 尾部 10.2s 毛刺 | 温度墙 / 内存碎片 | 2s 轮询周期的量化假象（WS 重测 max 只有 9.10s） |
| cudaMallocAsync +4s 开销 | 分配器劣化 | 真实开销 +2.6s，多出的 1.4s 是轮询量化 |
| 容器化 +5.8% 开销 | 容器税 | 热惯性 + 整卡显存口径 + page cache，净值 0.7% |

**轮询偏差的定量规律**：绝对误差固定（≤ 一个采样周期），所以**任务越快，相对误差越大**。

```
P100  任务 7.9s，最大误差 2s  →  相对误差  25%
5060  任务 1.9s，最大误差 2s  →  相对误差 105%   ← 误差比任务本身还长
```

后果：中位数只偏差 3~4%，但 **5060 的 P95 虚高 76%**——轮询的量化误差恰好制造假长尾，
而 P95 本身就是在捕捉长尾。**用 2 秒采样测 2 秒的任务，尾部指标就是噪声。**

**教训：**

- **采样间隔必须与被测对象的时间尺度匹配。** 这条直接约束了 Prometheus 的抓取设计（见 04 手册 §6.4）。
- **A/B 实验先排除干扰变量，再看净差异。** 只看中位数就写"容器开销 5.8%"是错的。
- **表观读数 ≠ 真实开销。** 这是本项目重复踩了三次的坑。

### 修正 4 & 5：六连败之后，最后一行才是根因

LoRA 生成"双头/多头/无狗"，前四次诊断全错。错误不在于不够聪明，而在于**没有用排除法组织搜索**。

| 嫌疑 | 对照设计 | 结果 |
| --- | --- | --- |
| 数据集多样性 | 多样（v1）vs 一致（v2/v4） | 都失败 → 排除 |
| 优化器 | AdamW8bit vs AdamW | 都失败 → 排除 |
| 强度 | 0.1~0.8 全扫 | 都失败 → 排除 |
| 文本编码器 | 同 LR vs 半速 LR | 都失败 → 排除 |
| 推理环境 | P100 vs RTX 5060 | 都失败 → 排除 |
| 触发词 | myshiba vs shiba inu | 都失败 → 排除 |
| **生成分辨率** | **512×512 → 768×512** | **✅ 一张完整的狗** |

**真根因**：训练数据（Stanford 柴犬）绝大多数为横向构图，LoRA 学到"狗在横向画框里"。
生成 512×512 正方形时横向构图塞不下，模型平铺出第二个头。

**教训：**

1. **列全嫌疑变量，逐一设计对照实验排除，而不是凭直觉猜。** 直觉会让你在错误方向上连做四个实验。
2. **一次只改一个变量。** 同时改两个，失败时你不知道是谁的锅。
3. **"假基线"也是陷阱。** 用 `strength=0` 但提示词里仍带自造词当基线，结果被未训练 token 的噪声污染——
   对照实验里"基线"和"测试"的提示词必须**只差触发词本身**。
4. **修正 5 是修正 4 的连带平反**：v1/v2 从未在正确画幅下被评测过，所以"AdamW8bit 算错"这个指控
   从一开始就建立在一个没做过的实验上。**一次误诊会污染后续所有结论。**

> 这条教训在 SDXL 上得到了回报：评测直接用 640×448（匹配训练构图），
> **一次通过，未重蹈四轮覆辙**。教训被前置应用，就是它产生价值的方式。

### 修正 6：下"平台不支持"结论前，先确认被测对象当时存在

阶段三测试 `nvidia-smi --query-compute-apps` 返回空表，判定"Proxmox 透传下拿不到 per-process 归属"。

**错在哪**：该命令**只列出 compute（C 型）进程**。若测试时刻 GPU 上只有 Xorg（G 型）而没有计算进程，
输出就只有表头，看起来像"不支持"。后来在 llama-server（11236 MiB）与 venv python（254 MiB）
同时占卡时实测，归属信息完整。

**教训：**

- **空结果不等于不支持。** 先确认"被测对象当时是否存在"，再判定能力边界。
- 已无法回溯确证当时的环境，所以这条**只记录最可能的原因，不装作已经定因**。
- 这次是被用户质疑后复测才发现——**别人的质疑是最便宜的错误检测机制，别抗拒它。**

## 三、沉淀出的方法论（可复用的检查清单）

### 3.1 下结论前

- [ ] 证据链里哪些是**实测**、哪些是**推断**？逐条标注了吗？
- [ ] 结论的措辞是否**收窄到实测范围**？有没有偷偷推广？
- [ ] 样本量够吗？**一台机器的现象能推广到一类机器吗？**
- [ ] 多变量同时不同时，有没有承认**无法定因**？

### 3.2 测量前

- [ ] **量具校准了吗？**（采样间隔 vs 被测对象的时间尺度）
- [ ] 首张/首次请求是不是**缓存命中**？（图像 execution cache / LLM KV 前缀缓存）
- [ ] 冷/热态分开统计了吗？
- [ ] 指标公式本身用**实测行为**校准过吗？（并发判定用 max/min 而非 wall vs sum）

### 3.3 A/B 实验

- [ ] 干扰变量排除了吗？（热惯性 / 整卡口径 / page cache / 环境温度）
- [ ] 一次只改一个变量吗？
- [ ] 对照组的设计**真的只差那个变量**吗？（假基线陷阱）

### 3.4 改造后

- [ ] **复测了吗？** 不复测的改造等于没做。

> 散热改造就是最好的例子：风扇装了（以为解决了），09-21 复测双阴性（79°C 依旧、PL170W 更差），
> 09-22 换导风罩 + 空调环境才拿到阳性（快 7.4~8.1%）。
> **"装了"和"解决了"是两回事。**

## 四、为什么不删改历史

本文档与 benchmarks 中的修正记录**全部保留原结论 + 证伪证据 + 日期，划线保留而不是删掉**。

理由：

1. **删掉就只剩结论，看不出判断力。** 需要呈现的是怎么发现问题，而不只是最终答案对不对。
2. **生产事故的复盘报告里，最怕的就是"看起来合理但没验证"的归因。** 保留错误链条，
   才能让下一次不再犯同一类错。
3. **能自我证伪本身就是能力。** 大部分人会把错误悄悄改掉，假装从没错过——
   那样就永远失去了从错误里学习的机会。

> **一句话**：**能区分证据与推理、能自我证伪，是我认为 Infra 工作最核心的素质。**
