# 企业内网 AIGC 平台私有化部署方案

> **文档用途**：为企业内网环境提供图像生成 + LLM 推理的一体化私有化部署方案，覆盖选型、架构、安全、运维、成本的完整决策依据。
> **读者对象**：企业 IT 负责人、架构评审、运维团队。
> **版本**：V1.0（2026-09-20）
> **数据声明**：本方案全部性能数字来自一套真实运行的双机验证平台（RTX 5060 开发端 + Tesla P100 算力端）的**实测基准**（见随附《benchmarks-实测数据.md》，170+ 图像样本、3 轮 LLM 基准），非厂商标称值。

---

## 1. 方案概述

### 1.1 目标

在企业内网部署一套**数据不出网、无外网依赖、可统一管控**的 AIGC 推理平台，提供：

- **图像生成**：SD 1.5 / SDXL + 企业自有 LoRA（产品图、营销素材、设计辅助）
- **文本生成**：本地 LLM（文档摘要、内部知识问答、代码辅助）
- **统一入口**：API 网关 + 鉴权 + 审计 + 队列管控，对接内部系统
- **统一运维**：GPU/服务/任务三层监控告警，容量可规划

### 1.2 设计原则

| 原则 | 落地方式 |
| --- | --- |
| **数据不出内网** | 全组件本地部署；模型离线分发；构建不依赖外网（本地 tar + wheels + 版本锁） |
| **最小暴露面** | 服务默认绑回环/网桥地址，按需精确开放；无鉴权端点不出管理网段 |
| **一切可度量** | 性能、容量、告警阈值全部来自实测，不拍脑袋 |
| **可复现交付** | 镜像字节级可复现（源码 tar + commit + requirements.lock） |

### 1.3 验证平台说明（本方案的证据基础）

本方案在一套异构双机平台上完成全链路验证，**两代架构的兼容性坑均已踩平**：

| 角色 | 配置 | 验证内容 |
| --- | --- | --- |
| 算力节点 | Tesla P100 16G（Pascal sm_60，Proxmox 透传 VM，24G RAM） | 推理/训练/监控/容器化全链路 |
| 开发节点 | RTX 5060 8G（Blackwell sm_120，Windows 11） | 快速迭代、双机一致性验证 |

企业部署时算力节点可按 §3 的选型矩阵替换为更新代际的 GPU，**方案架构与运维体系不变**。

## 2. 典型业务场景与容量需求

| 场景 | 负载特征 | 容量估算依据 |
| --- | --- | --- |
| 营销素材批量生成 | 批量、可排队（异步） | 吞吐（张/分）× 批次窗口 |

## 3. 硬件选型与算力估算

### 3.1 实测性能基线（选型的输入数据）

**图像生成（SD 1.5，512×512/20步，WebSocket 精测，n=20）：**

| 指标 | RTX 5060 8G | Tesla P100 16G |
| --- | --- | --- |
| 单张中位耗时 | **1.94 s** | 7.90 s |
| 稳态吞吐 | **27.9 张/分** | 7.5 张/分（温度墙降频后 ~6.4） |
| 大分辨率（768×512/25步 + LoRA） | — | 17.7 s/张，3.6 张/分 |
| 显存占用 | 3.2 GB | 2.5~2.8 GB |

**LLM 推理（llama.cpp，9B Q8_0 / P100）：**

| 指标 | 实测值 | 说明 |
| --- | --- | --- |
| decode | **28.7 tok/s** | 内存带宽硬顶，与上下文长度无关 |
| prefill | **513 tok/s** | 调优后（ubatch 256，见 §3.4） |
| TTFT（短对话） | **0.29 s** | 交互体验达标 |
| 14B Q4_K_M | 22.5 tok/s | 能力升级的性能代价约 -22% |

### 3.2 选型矩阵

| 档位 | 配置 | 适用规模 | 说明 |
| --- | --- | --- | --- |
| **验证/小微团队** | 1× 消费卡（4060 Ti 16G / 5060） | ≤ 10 人 | 成本最低，SD1.5 体验好；LLM 限 9B 内 |
| **部门级（本方案基线）** | 1× 数据中心卡 16G+（P100/4090/A10） | 10~50 人 | 图像 + 9B LLM + LoRA 训练全覆盖 |
| **企业级** | 2~4× 24G+ 卡（4090/A10/A30） | 50~200 人 | SDXL + 14B+ LLM；多实例横向扩展（单实例串行，吞吐线性叠加） |

**关键认知（实测）**：推理服务**单实例串行执行**，批量调度开销 < 1%——**提吞吐只有三条路：加卡、加实例、改善散热**。并发不是软件调出来的，是硬件堆出来的。

### 3.3 散热是容量规划的一等公民（实测）

验证平台实测 P100 存在**温度墙**：满载 ~70 秒触及 79°C 拐点，SM 频率 1328→1050MHz，**吞吐损失 13~30%（单张工作量越大损失越狠）**，频率-耗时比 1.155≈1.157 严丝合缝。

| 决策 | 数据支撑 |
| --- | --- |
| 机架选型必须保证前进后出风道 | 全程满频可提吞吐 **+15%** |
| 告警阈值用实测拐点（79°C），不用厂商理想值 | 写 80°C 会漏报（温度在拐点震荡） |

### 3.4 软件调优的免费午餐（实测）

同一硬件，纯配置调整带来的收益：

| 调优项 | 收益 | 成本 |
| --- | --- | --- |
| LLM `--ubatch-size 256` | **prefill 3.2×**（162→513 tok/s） | 零 |
| 显存分配器切换（5060 专属） | 单张 4.54→1.94s（**2.3×**） | 零 |
| PyTorch 碎片治理（`expandable_segments`） | 多服务共存可用显存 +1.7G | 零 |

**先榨干软件调优，再谈硬件扩容。**

## 4. 总体架构

```
┌─────────────────────────── 企业内网 ───────────────────────────┐
│                                                                │
│  内部系统/用户                                                 │
│      │  HTTPS + API Key                                        │
│      ▼                                                         │
│  ┌──────────────────────────────────────────────────────┐     │
│  │  AIGC 统一网关（FastAPI）                             │     │
│  │  鉴权 / 审计 / 任务队列 / GPU 准入控制 / 限流          │     │
│  └───────┬──────────────────────────┬───────────────────┘     │
│          ▼                          ▼                          │
│  ┌───────────────┐        ┌─────────────────┐                 │
│  │ ComfyUI 推理   │        │ llama-server    │                 │
│  │ （图像/LoRA）  │        │ （LLM/Embedding）│                │
│  └───────────────┘        └─────────────────┘                 │
│          │                          │                          │
│  ┌───────┴──────────────────────────┴───────────────────┐     │
│  │  三层监控：dcgm（硬件）+ 应用 metrics（服务）+ 网关指标 │     │
│  │  Prometheus → Grafana → 告警（实测阈值）              │     │
│  └──────────────────────────────────────────────────────┘     │
│                                                                │
│  模型库（内部分发）/ 训练环境（sd-scripts，与推理隔离）          │
└────────────────────────────────────────────────────────────────┘
```

**架构要点**：

- **网关是唯一入口**：鉴权、审计、队列、准入控制集中于此；推理服务（ComfyUI/llama-server）不对用户直接暴露
- **出图异步化**：提交→task_id→轮询/回调，天然适配队列与批处理；LLM 流式透传保交互体验
- **GPU 准入控制**：任务执行前查显存水位，不足则排队/拒绝——**代替裸 OOM**（验证平台实测事故后的工程产出）
- **训练与推理隔离**：独立 venv/目录/资源窗口，训练用夜间时段（连续满载数十分钟，必撞温度墙，时长 +15% 计入排程）

## 5. 对外服务与集成

> 平台的价值最终体现在"业务系统能不能方便、安全地调用"。本章定义对外服务目录、暴露路径、消费模式与集成方式。

### 5.1 服务目录（对外 API 清单）

| 能力 | 端点 | 模式 | 典型消费方 |
| --- | --- | --- | --- |
| 文本生成 | `POST /v1/chat/completions` | 流式 / 非流式，**OpenAI 兼容** | 业务系统、内部工具、知识库问答 |
| 向量嵌入 | `POST /v1/embeddings`（embedding 实例 :8001） | 同步 | RAG 管道、语义检索 |
| 图像生成 | `POST /v1/images/generations` → `GET /v1/tasks/{id}` | **异步**（202 + task_id） | 营销/设计系统、批处理管道 |
| 结果下载 | `GET /files/{task_id}/{filename}` | 同步 | 调用方自取 |
| 健康与指标 | `GET /health` / `GET /metrics` | 运维专用 | 监控栈（不对业务开放） |

**"OpenAI 兼容"是关键的集成决策**：文本侧遵循 OpenAI API 规范，意味着 **LangChain / LlamaIndex / Dify / 各类 SDK 零改造接入**——业务方把 `base_url` 指向平台网关即可，学习成本与迁移成本都最低。图像侧无行业标准，采用"异步任务 + 轮询"的通用批处理模式（见 §5.3）。

### 5.2 对外暴露路径（按规模两级）

| 级别 | 适用 | 路径 | 控制点 |
| --- | --- | --- | --- |
| **部门级** | ≤ 50 人，可信内网 | 业务网段 → 网关（API Key 鉴权） | per-key 签发/吊销、审计日志 |
| **企业级** | 多部门/外部系统 | 业务网段 → **nginx 反向代理**（HTTPS 终止 + 统一认证 + 限流 + WAF）→ 网关 | TLS、LDAP/OAuth2、配额、IP 白名单 |

企业级参考配置（nginx）：

```nginx
server {
    listen 443 ssl;
    server_name aigc.internal.example.com;
    # ssl_certificate / oauth2-proxy / LDAP 认证略（按企业统一认证接入）

    location /v1/ {
        limit_req zone=aigc burst=10 nodelay;      # 限流：保护串行推理后端
        proxy_pass http://aigc-gateway:8300;
        proxy_set_header x-api-key $arg_key;        # 或走统一认证后注入内部 key
        proxy_read_timeout 600s;                    # 出图与长文本生成需要长超时
        proxy_buffering off;                        # 流式 SSE 必须关缓冲
    }

    # /metrics /files 不对外暴露，仅管理网段经 SSH 隧道/跳板访问
}
```

> **原则**：业务方只能看到反向代理的 443；网关、推理服务、监控端点全部不出管理网段（与 §6.1 的分区矩阵一致）。

### 5.3 异步任务的消费模式（图像/批处理）

出图是秒级~十秒级的批处理负载，且**推理后端单实例串行**（实测），因此采用异步模式。两种消费方式：

| 模式 | 状态 | 说明 |
| --- | --- | --- |
| **轮询** | ✅ 已实现 | 提交得 `task_id` → 客户端按退避间隔查询（建议 2s 起步、指数退避至 10s 封顶）→ `done` 后取 `files` 链接下载。简单可靠，适合绝大多数业务 |
| **Webhook 回调** | 路线（v2） | 任务完成时网关主动 POST 到业务系统回调地址。需要配套签名验证、失败重试、死信队列——**多系统高频接入时才值得做** |

**调用方的超时与预期管理**（实测数据标定）：

```
单张出图耗时：P100 512×512 ~8s / 768×512+LoRA ~18s（含温度墙降频）
队列等待：串行执行，排队时长 = 前面任务数 × 单张耗时
建议调用方超时：单张 60s，批量按 20s/张 × 张数 + 余量
网关 queue_wait / duration 分离上报，排队与执行可分别监控
```

### 5.4 最小集成示例

**文本（OpenAI SDK，零改造）：**

```python
from openai import OpenAI
client = OpenAI(base_url="https://aigc.internal.example.com/v1", api_key="<签发的key>")
for chunk in client.chat.completions.create(
        model="local", stream=True,
        messages=[{"role": "user", "content": "总结这份季度报告"}]):
    print(chunk.choices[0].delta.content or "", end="")
```

**图像（异步全流程）：**

```python
import requests, time
G, K = "https://aigc.internal.example.com", "<签发的key>"
H = {"x-api-key": K}

task = requests.post(f"{G}/v1/images/generations", headers=H, json={
    "prompt": "product photo of a ceramic mug, studio lighting",
    "width": 768, "height": 512, "steps": 25}).json()

while True:
    time.sleep(2)
    r = requests.get(f"{G}/v1/tasks/{task['task_id']}", headers=H).json()
    if r["status"] in ("done", "failed"):
        break
print(r["result"]["files"])   # ['/files/<id>/xxx.png'] → GET 下载
```

### 5.5 SLA 承诺方式（用实测纪律定指标）

对外承诺遵循平台的测量纪律：**用 P95 不用平均值，区分冷/热，声明队列语义**：

| 指标 | 参考值（验证平台实测） | 承诺建议 |
| --- | --- | --- |
| LLM 首 token 延迟 | 0.29s（热）/ 0.9s（含 kernel 加载） | P95 < 2s |
| LLM 解码速度 | 28.7 tok/s（单路） | ≥ 20 tok/s（单路） |
| 图像单张 | 8s（512²）/ 18s（768×512） | P95 + 排队时长公式公开 |
| 并发 | 串行 + 队列 | 不承诺并发数，承诺**排队可见性**（queue_depth 实时可查） |

> **不承诺做不到的事**：串行后端不承诺"并发响应"，而是承诺"队列深度透明 + 预期等待可计算"——这比拍一个兑现不了的 SLA 更能建立业务方信任。

## 6. 网络与安全架构

### 6.1 网络分区与暴露面控制（验证平台实测经验）

| 端点 | 绑定策略 | 可达范围 |
| --- | --- | --- |
| 推理服务（ComfyUI/llama-server） | 回环或精确接口 | 仅本机/容器网桥 |
| 网关 | 管理网段 + 精确绑定（实测：绑 docker0 网桥 IP 可兼顾容器监控与局域网隔离） | 管理网段 |
| 监控（Prometheus/Grafana） | 回环 + SSH 隧道/跳板 | 运维人员 |
| 对外服务 | 经反向代理（nginx + HTTPS + 统一认证） | 业务网段 |

**原则**：无鉴权端点（/metrics、/files、ComfyUI 全端口）**永不出管理网段**。验证平台曾实测 ComfyUI 绑 0.0.0.0 裸奔的风险（无鉴权，任何人可提交任务、枚举模型），已固化为基线检查项。

### 6.2 离线分发（无外网依赖）

验证平台的容器构建已全程离线化，方案直接复用：

```
模型/源码 → 内部制品库（tar + commit 文件追溯）
Python 依赖 → 内部 wheel 仓 + requirements.lock（精确版本，101 包字节级一致）
容器镜像 → 内部 registry（构建四要素：base 镜像 + 源码 tar + wheels + lock）
```

**离线构建的价值不仅是安全**：同一 Dockerfile 任何时间构建产出字节级一致——"pin 了 commit"必须配套依赖锁，否则只是锁住了代码、依赖树还在漂。

### 6.3 认证与审计

- **认证**：网关 API Key（按系统/团队签发），生产建议升级 nginx + OAuth2/LDAP 统一认证
- **审计**：网关是天然审计点——所有请求（prompt、参数、耗时、结果引用）过网关可全量记录，满足内容合规追溯
- **传输**：内网 HTTP + 反向代理终止 TLS；敏感行业叠加链路加密

## 7. 模型管理与合规

### 7.1 模型库治理

| 环节 | 机制 |
| --- | --- |
| 入库 | 统一模型库目录 + 审批流程；**只收 `.safetensors`，拒收 `.ckpt`**（pickle 反序列化可执行任意代码） |
| 版本 | 文件名含版本/日期；ComfyUI commit 与模型组合经过验证后登记基线 |
| 分发 | 内部制品库 → 各节点；大文件校验（sha256） |
| 训练产物 | LoRA 权重健康检查（张量统计、NaN/Inf 扫描）后方可入推理库 |

### 7.2 许可合规（重点提醒）

| 模型来源 | 许可风险 |
| --- | --- |
| SD 1.5 官方 | CreativeML Open RAIL-M，可商用但有用途限制条款 |
| **Civitai 社区 checkpoint** | ⚠️ **许可各不相同**：部分仅限非商用、部分禁止二次分发、部分基于限制性底模训练。**企业商用必须逐个核查 license，入模型库前留存许可证据** |
| FLUX 系列 | 注意 dev/schnell 的商用条款差异 |
| 自训 LoRA | 训练数据版权需自查（验证平台用 Stanford Dogs——**研究用途数据集，企业商用需换自有/授权素材**） |

### 7.3 内容安全

- 网关侧可插拔内容过滤（prompt 关键词 / 图像 NSFW 检测），按行业合规要求启用
- 审计日志保留周期按企业合规要求配置（建议 ≥ 180 天）

## 8. 多用户与容量管控

| 机制 | 现状（验证平台已运行） | 企业增强路线 |
| --- | --- | --- |
| 并发控制 | 推理单实例串行 + 网关队列 | 多实例 + 网关按 key 路由 |
| 公平性 | FIFO 队列 | 按 key 配额 / 优先级队列 |
| 隔离 | 任务输出按 task_id 分目录 | 按租户目录 + 配额 |
| 容量预警 | 队列深度为核心健康指标（实时监控） | 队列深度 > N 触发扩容评审 |

**容量规划公式（实测标定）**：

```
单节点日图像产能 = 稳态吞吐 × 降频系数(0.7~0.85) × 有效工时
  例：P100 SD1.5 ≈ 7.5 × 0.75 × 60 × 8h ≈ 2700 张/工作日
LLM 交互容量 ≈ 串行 decode 28.7 tok/s → 单路体验好，多路排队，
  并发 ≥ 3 路时建议加实例（每实例独立显存 ~10G）
```

## 9. 运维监控体系（已在验证平台运行）

### 9.1 三层监控

| 层 | 组件 | 内容 |
| --- | --- | --- |
| 硬件层 | dcgm-exporter → Prometheus → Grafana | 温度/频率/功耗/显存/利用率，5s 采样（**采样间隔必须匹配被测对象时间尺度**，实测教训） |
| 服务层 | llama-server `--metrics` / 网关 `/metrics` | token 速率、队列深度、任务耗时、失败率 |
| 告警 | Prometheus rules | **阈值全部实测标定**（温度 79°C 拐点、频率 1200MHz 防抖、XID 出现即 critical） |

**告警设计哲学**：阈值用实测拐点不用理想值——"该响的时候响"是第一要务。天天吵的告警 = 没人看的告警。

### 9.2 可用性

- 全服务 systemd 托管：`Restart=on-failure` + `StartLimitBurst`（防无限重启刷爆日志，实测坑）
- 容器服务 compose 编排 + 健康检查 + 日志轮转（50m×5）
- 升级流程：镜像 tag 灰度替换，秒级回滚（镜像不变即回退）

### 9.3 备份策略

| 内容 | 策略 |
| --- | --- |
| 模型库 | 定期快照 + 异地副本（3-2-1 原则），变更才触发 |
| 训练产物（LoRA/数据集/配置） | 每训练周期归档，训练配置（toml/脚本）随产物一起存 |
| 平台配置（compose/systemd/网关代码/监控规则） | Git 版本控制，异地 remote |
| 监控数据 | Prometheus 30 天保留，长期趋势导出归档 |

## 10. 成本测算（TCO 模型）

> 价格为 2026-09 参考量级（二手市场价/主流算力平台按量价），**替换为询价实数即可**，模型不变。

### 10.1 单节点（部门级）三年 TCO

| 项 | 本地部署 | 云端算力（A10 档按量） |
| --- | --- | --- |
| 硬件 | ¥10,000（二手数据中心卡整机） | — |
| 电费 | 250W × 24h × ¥0.6/度 ≈ ¥110/月 → ¥3,960/3年 | — |
| 算力费 | — | ¥1.9/h × 720h ≈ ¥1,370/月 → ¥49,300/3年 |
| 运维人力 | 0.1 人月/年（平台成熟后） | 同 |
| **三年合计** | **≈ ¥17,000 + 人力** | **≈ ¥49,300 + 人力** |

**盈亏平衡 ≈ 8 个月**（此后本地每用一个月净省 ~¥1,260）。

### 10.2 什么时候选云端

| 场景 | 建议 |
| --- | --- |
| 负载稳定持续（利用率 > 40%） | **本地**（按量云是为弹性付费，稳定负载是浪费） |
| 脉冲式/项目制 | 云端按需，或本地+云端溢出（混合） |
| 数据敏感/合规要求不出网 | **只能本地** |
| 需要最新大模型（70B+） | 云端短期租用，本地不追旗舰 |

### 10.3 隐性成本提醒（实测经验）

- **版本治理是人力大头**：驱动/CUDA/PyTorch/框架的兼容矩阵需要维护（本方案的版本锁定基线可直接复用，显著降低此成本）
- **散热不达标 = 隐性算力税 13~30%**（实测），机房环境投入不能省
