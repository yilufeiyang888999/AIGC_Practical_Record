# AIGC 平台使用指南（角色与操作示例）

> **文档用途**：告诉平台的三类用户——业务系统、开发者/集成方、运维管理员——**拿到平台后第一步做什么、怎么调用、出错怎么办**。
> **适用环境**：部门级部署（网关直连 + API Key）。企业级（nginx 反代）仅接入地址不同，调用方式完全一致。
> **版本**：V1.0（2026-09-20，对应 aigc-gateway v0.1）

---

## 0. 角色速览与接入信息

| 角色 | 你要做什么 | 入口 | 需要什么 |
| --- | --- | --- | --- |
| **业务系统** | 在自己的系统里调 API（出图/对话） | `http://<网关>:8300/v1/*` | 向运维申请 **API Key** |
| **开发者/集成方** | 联调测试、性能验证、二次开发 | `/docs`（开发环境）+ 基准脚本 | 开发环境地址 + key |
| **运维管理员** | 巡检、密钥管理、服务管理、故障处理 | SSH + Grafana + systemd | 服务器权限 |

**接入地址（按部署形态）**：

| 形态 | 地址 | 说明 |
| --- | --- | --- |
| 部门级（内网直连） | `http://<网关IP>:8300` | 业务网段直达 |
| 企业级（nginx 反代） | `https://aigc.<公司域名>` | 统一认证 + HTTPS，路径不变 |
| 开发机经 SSH 隧道 | `http://127.0.0.1:8300` | ssh config 加 `LocalForward 8300 172.17.0.1:8300` |

**所有 `/v1/*` 请求必须带请求头**：`x-api-key: <你的key>`（不带 → 401）。

## 1. 业务系统（主要消费者）

### 1.1 文本生成（对话/摘要/问答）

OpenAI 兼容协议——**任何支持 OpenAI 的 SDK/框架，把 `base_url` 指向平台即可**。

**curl 最小示例：**

```bash
curl -N -X POST http://<网关>:8300/v1/chat/completions \
  -H "x-api-key: <你的key>" -H "Content-Type: application/json" \
  -d '{
    "model": "local",
    "messages": [{"role": "user", "content": "把这段文字总结成三点：<正文>"}],
    "max_tokens": 512,
    "stream": true
  }'
```

**Python（OpenAI SDK，推荐）：**

```python
from openai import OpenAI

client = OpenAI(base_url="http://<网关>:8300/v1", api_key="<你的key>")

resp = client.chat.completions.create(
    model="local",
    messages=[{"role": "user", "content": "用三句话介绍我们的产品"}],
    max_tokens=512,
)
print(resp.choices[0].message.content)
```

**集成方必读的三条实测经验**：

| 事项 | 说明 |
| --- | --- |
| `max_tokens` 要给足 | 平台主力模型是**思考型**（先输出推理过程再给答案），预算太小会"想完了没说完"。建议 ≥ 512 |
| 并发请求会排队 | 后端单槽串行（实测）：两个请求同时发，第二个等第一个跑完。**客户端超时要含排队余量**（单请求建议 ≥ 60s） |
| 首 token 快 ≠ 全文快 | TTFT ~0.3s（交互感好），全文速度 ~28 tok/s——估算总时长用 `token数 ÷ 25` |

### 1.2 图像生成（异步任务）

出图是 8~18 秒的批处理，**异步模式**：提交 → 拿 task_id → 轮询 → 下载。

**完整可跑的 Python 示例：**

```python
import requests, time

GATEWAY = "http://<网关>:8300"
HEADERS = {"x-api-key": "<你的key>"}

# ① 提交（202 表示已入队，不是已完成）
resp = requests.post(f"{GATEWAY}/v1/images/generations", headers=HEADERS, json={
    "prompt": "shiba inu, 1dog, solo, sitting, best quality, detailed fur",
    "width": 768, "height": 512,     # 默认即 768×512（LoRA 横屏）
    "steps": 25,                      # 默认 25
    # "seed": 12345,                 # 不传则随机；固定 seed 可复现同一张图
}, timeout=10)
resp.raise_for_status()
task_id = resp.json()["task_id"]
print(f"已入队: {task_id}, 前面还有 {resp.json()['queue_depth']} 个任务")

# ② 轮询（2s 起步，别狂刷——结果不会更快，还给网关添负载）
while True:
    time.sleep(2)
    r = requests.get(f"{GATEWAY}/v1/tasks/{task_id}", headers=HEADERS, timeout=10).json()
    if r["status"] == "done":
        break
    if r["status"] == "failed":
        raise RuntimeError(f"出图失败: {r['error']}")

# ③ 下载
for url in r["result"]["files"]:
    img = requests.get(f"{GATEWAY}{url}", headers=HEADERS)
    fname = url.split("/")[-1]
    open(fname, "wb").write(img.content)
    print(f"已保存: {fname}（排队 {r['queue_wait_s']}s + 执行 {r['elapsed_s']}s）")
```

**批量出图的正确姿势**：循环提交（每个任务拿自己的 task_id），**不要**等前一个 done 再交下一个——网关队列就是干这个的，灌进去让它串行消化，最后统一收结果。调用方总超时按 `20s × 张数 + 60s 余量` 估算。

### 1.3 错误处理速查（业务方）

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 401 | key 缺失/错误 | 检查 `x-api-key` 头 |
| `failed` + "GPU 准入拒绝" | 显存被其他服务占用，等 120s 未释放 | **可重试**（指数退避）；频繁出现找运维 |
| `failed` + 其他 error | 后端执行失败 | error 字段有详情，连 task_id 一起报给运维 |
| 提交后长时间 pending | 队列积压 | 查 `queue_depth`；持续 > 5 找运维扩容评估 |

## 2. 开发者 / 集成方

### 2.1 交互式联调（Swagger UI）

浏览器打开 `/docs`（**生产环境同样开放**——页面只展示 API 结构，调用行为仍由 key 把守）：

```
http://127.0.0.1:8300/docs
```

每个端点都可以**在线填写参数、直接调用、看真实响应**——联调阶段最快的验证方式。
**生产实例调用 /v1/* 前，先点页面右上角 `Authorize` 按钮粘贴 API Key**（之后所有 "Try it out" 会自动带上 `x-api-key` 头）。

### 2.2 性能验证（验收/选型用）

平台附带两个基准脚本（`scripts/`），输出结构化 JSON/CSV：

```bash
# LLM 基准：TTFT / prefill / decode / 并发行为
set LLM_HOST=http://<llama-server>:8000
python llm_bench.py

# 图像基准：耗时分布 / 吞吐 / 成功率 / 显存
set COMFY_HOST=http://<comfyui>:8188
python comfy_batch_gen.py
```

**验收对照基线**（验证平台实测，你的环境应接近）：LLM decode 28.7 tok/s、prefill 513 tok/s；SD1.5 512×512 单张 7.9s（P100）/ 1.94s（5060）。偏差 > 20% 先查温度墙（`nvidia-smi` 看温度/频率）和显存分配器参数。

### 2.3 接入 LLM 应用框架

| 框架 | 配置 |
| --- | --- |
| LangChain | `ChatOpenAI(base_url="http://<网关>:8300/v1", api_key=key, model="local")` |
| LlamaIndex | 同上，OpenAI 兼容配置 |
| Dify / One-API 类 | 添加"OpenAI 兼容"供应商，填 base_url + key |

### 2.4 图像能力定制

- **换风格**：改 `prompt`/`negative`（平台当前挂的是柴犬 LoRA，触发词 `shiba inu`；企业部署时换自有 LoRA 与触发词）
- **换分辨率**：`width`/`height`（256~1536）。⚠️ **分辨率必须匹配 LoRA 训练数据的构图比例**，横屏训练的 LoRA 用正方形会出多头/畸形（平台实测教训，见 05 手册 §8）
- **固定 seed**：复现同一张图（审计/回归测试用）

## 3. 运维管理员

### 3.1 每日巡检（5 分钟）

```bash
# ① 服务存活（三个都应 active/running）
systemctl status comfyui aigc-gateway --no-pager | grep -E "●|Active"
curl -s http://172.17.0.1:8300/health        # {"status":"ok",...}

# ② 监控抓取（四个都应 up）
curl -s localhost:9090/api/v1/targets | python3 -c "
import sys,json
for t in json.load(sys.stdin)['data']['activeTargets']:
    print(t['labels']['job'], t['health'])"

# ③ GPU 状态（温度 < 79°C 拐点；显存水位）
nvidia-smi --query-gpu=temperature.gpu,clocks.sm,memory.used --format=csv
```

Grafana（`http://127.0.0.1:3000`，经 SSH 隧道）看温度/频率/显存趋势；**队列深度 `aigc_image_queue_depth` 是平台最重要的业务健康指标**。

### 3.2 密钥管理

```bash
# 密钥存放：/opt/AIGC/aigc-gateway/.env（chmod 600，不进版本库）
# 更换/吊销：
vi /opt/AIGC/aigc-gateway/.env        # 改 AIGC_API_KEY
sudo systemctl restart aigc-gateway   # 即时生效，旧 key 全部失效
```

> v0.1 是单 key（全平台一个）。多用户/per-key 配额在 v2 路线（网关代码已预留鉴权中间件位置）。

### 3.3 服务管理速查

| 操作 | 命令 |
| --- | --- |
| 启停网关 | `sudo systemctl {start\|stop\|restart} aigc-gateway` |
| 启停 ComfyUI | `sudo systemctl {start\|stop\|restart} comfyui` |
| 看日志 | `journalctl -u aigc-gateway -f` / `tail -f /opt/AIGC/logs/comfyui.log` |
| 切换 LLM 模型 | `/opt/llama.cpp/llm-switch.sh`（交互菜单；自带 GPU 占用检测） |
| 改配置后重载监控 | `curl -X POST localhost:9090/-/reload`（仅 Prometheus 配置） |

### 3.4 常见故障处置

| 症状 | 定位 | 处置 |
| --- | --- | --- |
| 网关 502/连接拒绝 | `systemctl status aigc-gateway` | 看 journalctl；多为后端（ComfyUI/llama-server）挂了 |
| 出图全 failed + "准入拒绝" | `nvidia-smi` 看显存被谁占 | 训练任务在跑？等它完；否则重启占卡服务 |
| 出图变慢 30% | Grafana 温度曲线 ≥ 79°C | 温度墙（正常物理现象）；长期考虑散热改造 |
| LLM 首请求特别慢（~1s） | 服务刚重启 | kernel 加载税，发一个 warmup 请求即可 |
| 队列深度持续 > 5 | 业务高峰或后端变慢 | 先查温度墙，再评估加实例（容量公式见 07 §8） |

### 3.5 扩缩容判断（实测标定）

- **加实例信号**：`aigc_image_queue_depth` 工作时间持续 > 5，或业务方报排队不可接受
- **散热信号**：降频时段占比 > 30%（Grafana 频率曲线）→ 散热改造 ROI 最高（+15% 吞吐，零硬件成本）
- **加卡信号**：单实例满频仍供不应求（吞吐上限：SD1.5 ~7.5 张/分/P100，实测）
